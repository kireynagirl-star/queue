# ระบบคิวรับสินค้าออนไลน์ (Express + Supabase)

ระบบต้นแบบพร้อมรัน มีฐานข้อมูลกลางและหน้าจอสำหรับพนักงาน/จอเรียกคิว รองรับมือถือและคอมพิวเตอร์

## ฟังก์ชัน

- ออกเลขคิวรายวันแยกตามประเภท เช่น A001, A002… และ C001, C002… (เริ่มนับใหม่ตามวันที่กรุงเทพฯ)
- ออกคิวได้ 2 ประเภทเท่านั้น: A001, A002… และ C001, C002… โดยไม่ต้องกรอกข้อมูล
- เรียกคิว, กลับไปรอ, ทำเครื่องหมายรับสินค้าแล้ว
- หน้าจอแสดงคิวที่กำลังเรียกและคิวรอ อัปเดตทุก 5 วินาที
- ข้อมูลแชร์ผ่านฐานข้อมูล Supabase กลาง
- หน้าจอพนักงานมีรหัสผ่าน

## ข้อสำคัญ

**ระบบนี้ยังไม่เชื่อมกับระบบชำระเงินหรือยืนยันยอดเงินจริง** พนักงานต้องตรวจสอบการชำระเงินด้วยตนเองก่อนกดออกคิว ระบบจะไม่ตรวจสอบสลิปหรือเรียก payment gateway

## สิ่งที่ต้องใช้

- บัญชี Supabase สำหรับฐานข้อมูล
- บัญชีผู้ให้บริการโฮสต์ Node.js เช่น Render หรือ Railway (อาจมีข้อจำกัด/ค่าใช้จ่ายตามนโยบายปัจจุบัน)
- Node.js 20 ขึ้นไป สำหรับทดสอบในเครื่อง

แอปพลิเคชันโค้ดนี้ไม่มีค่าบริการไลเซนส์ แต่ไม่สามารถรับประกันว่าโฮสต์ออนไลน์และฐานข้อมูลจะฟรีตลอดไป ควรตรวจสอบแพ็กเกจและข้อจำกัดของผู้ให้บริการก่อนใช้งานจริง

## ขั้นตอนที่ 1 — สร้างฐานข้อมูล Supabase

1. สร้างโปรเจกต์ใน https://supabase.com/
2. เปิดเมนู **SQL Editor** แล้วสร้าง query ใหม่
3. เปิดไฟล์ `supabase-schema.sql` คัดลอกทั้งหมดไปวาง แล้วกด **Run**
4. ไปที่ **Project Settings → API** (หรือหน้า API Keys ตาม UI ปัจจุบัน) แล้วคัดลอก Project URL และ `service_role` / secret key ที่เซิร์ฟเวอร์ใช้ได้
5. เก็บ service-role key เป็นความลับ ห้ามใส่ใน HTML, JavaScript ฝั่งเบราว์เซอร์, GitHub public repository หรือส่งให้ลูกค้า

## ขั้นตอนที่ 2 — ตั้งค่าในเครื่อง

1. ติดตั้ง Node.js 20+ จาก https://nodejs.org/
2. แตก ZIP นี้ในโฟลเดอร์ที่ต้องการ
3. คัดลอก `.env.example` เป็น `.env`
4. แก้ `.env`:
   - `SUPABASE_URL` = Project URL
   - `SUPABASE_SERVICE_ROLE_KEY` = key ฝั่งเซิร์ฟเวอร์จาก Supabase
   - `STAFF_PASSWORD` = รหัสผ่านยาวอย่างน้อย 12 ตัวอักษร (แนะนำให้สุ่มและไม่ใช้ซ้ำ)
   - `DISPLAY_PASSWORD` ปล่อยว่างเพื่อให้จอเรียกคิวอ่านอย่างเดียวได้โดยไม่ต้องล็อกอิน หรือกำหนดรหัสหากต้องการจำกัดการดู
5. เปิด Terminal/Command Prompt ในโฟลเดอร์นี้ แล้วรัน:

   ```bash
   npm install
   npm start
   ```

6. เปิด http://localhost:3000 เพื่อจัดการคิว และ http://localhost:3000/display สำหรับหน้าจอเรียกคิว
7. ทดลองสร้างคิวและอัปเดตสถานะ

## ขั้นตอนที่ 3 — เผยแพร่ให้เปิดจากหลายเครื่อง

ตัวอย่างใช้ Render (ตรวจสอบราคาและนโยบาย sleep ของแพ็กเกจปัจจุบันก่อน):

1. อัปโหลดโฟลเดอร์โครงการเข้า **GitHub private repository** (ห้ามอัปโหลด `.env`)
2. สร้าง Web Service จาก repository ในผู้ให้บริการโฮสต์ Node.js
3. Build command: `npm install`
4. Start command: `npm start`
5. เพิ่ม Environment Variables จาก `.env` ในหน้า Settings ของผู้ให้บริการ
6. Deploy แล้วเปิด URL HTTPS ที่ผู้ให้บริการให้
7. ใช้ URL เดียวกันทุกอุปกรณ์:
   - พนักงาน: `https://YOUR-SITE.example/`
   - จอแสดงคิว: `https://YOUR-SITE.example/display`

การเปิด URL เดียวกันจากหลายอุปกรณ์จะอ่าน/เขียนฐานข้อมูลเดียวกัน หน้าจอรีเฟรชทุก 5 วินาที จึงไม่ใช่การอัปเดตแบบ WebSocket ทันที

## ความปลอดภัยและการใช้งานจริง

- ใช้ HTTPS เมื่อออนไลน์ และตั้ง `STAFF_PASSWORD` ที่เดายาก
- เก็บ Supabase service-role key เฉพาะใน environment variables ฝั่งเซิร์ฟเวอร์เท่านั้น
- จอแสดงคิวจะแสดงชื่อและรายการสินค้า จึงควรใช้ชื่อเล่น/ข้อมูลเท่าที่จำเป็น และตั้ง `DISPLAY_PASSWORD` หากไม่ต้องการให้บุคคลทั่วไปเข้าถึง
- ระบบเริ่มต้นนี้ยังไม่มีการจำกัดความถี่การล็อกอิน, การจัดการผู้ใช้หลายระดับ, การสำรองข้อมูลอัตโนมัติ หรือ audit log เหมาะกับการทดลอง/ร้านขนาดเล็กหลังตรวจสอบความปลอดภัยแล้ว
- การสร้างคิวใช้การอ่านเลขล่าสุดแล้วเพิ่มหนึ่ง พร้อม unique constraint และ retry แต่ร้านที่มีการออกคิวพร้อมกันจำนวนมากควรปรับเป็น PostgreSQL sequence/RPC transaction เพื่อให้การจัดเลขเป็น atomic
- วันคิวอิงเวลา Asia/Bangkok
- อย่าใช้ระบบนี้เป็นหลักฐานการรับชำระเงิน เพราะไม่ได้เชื่อมต่อ payment gateway

## โครงสร้างไฟล์

- `server.js` — API และเซิร์ฟเวอร์
- `supabase-schema.sql` — สร้างตารางและสิทธิ์ฐานข้อมูล
- `public/index.html`, `public/app.js` — หน้าพนักงาน
- `public/display.html`, `public/display.js` — หน้าจอเรียกคิว
- `public/style.css` — รูปแบบหน้าจอรองรับมือถือ
- `.env.example` — ตัวอย่างการตั้งค่าลับ
